# Figure 解读格式规范

读取 MinerU 清洗后的全文 MD，每张 Figure（主图 + 补充图）按以下格式输出。

## 总结构

```
## Overview
- **研究背景**：...
- **研究问题**：...
- **研究脉络**：...
- **主要方法**：...
- **关键结论**：...
- **意义**：...

## Figure X. Title

![[<64位hex>.png]]   ← 高清整图嵌入：紧跟标题、先于叙事（见「图片嵌入」节）

> **叙事位置**：一句话说明该图在全文中要回答的问题。

**Panel A — 描述**
> 原文 Legend
- **是什么**：...
- **为什么**：...
- **怎么做**：...
- **发现**：...

... 逐 panel ...

---

## Figure SX. Title        ← 补充图与主图相同格式，逐图排版（旧表格格式已废弃）

![[<64位hex>.png]]

> **叙事位置**：...
```

## 图片嵌入

- **唯一图片来源**：`scripts/render_pdf_figure.py` 从该篇 **canonical 主 PDF**（`<paper_dir>/<citation_key>.pdf`）以 ≥300 dpi 渲染的**完整整图** PNG（`![[<64位hex>.png]]`，content-addressed，已落该篇 `<paper_dir>/figures/`）。MinerU JPG（低像素碎片）只作定位线索，**不进入附件目录**，也绝不作为插图。
- **流程**：对每张主图/补充图——① 在 canonical 主 PDF 中定位 caption 页；② 渲染临时整页预览（/tmp）供视觉确认；③ 视觉确认 bbox 恰好框住**完整整图**（含全部 panel/子标签，不含 caption 与正文）；④ 调 `render_pdf_figure.py` 输出 300dpi PNG 到该篇 `<paper_dir>/figures/`；⑤ 同一 `![[<64位hex>.png]]`（同一文件、同一 embed）先嵌入 minerUmd 对应 Figure legend 前，再在 Figure解读 对应 `## Figure X/SX` 标题**之后、叙事位置之前**嵌入。
- **每图只放一张完整整图**：禁止把 panel/图标碎片堆进笔记；某图无法从主 PDF 可靠定位完整整图时，该位置写「*原 PDF 未能可靠定位完整 Figure*」，**不得猜裁**、不得张冠李戴。
- **同图多张**（罕见，整图分页排版）按原 PDF 顺序排列，仍只放完整整图。
- 旧布局（legacy）曾把高清 PNG 落 `<paper_dir>/Figure_<paper_title>/`；该布局已废弃，迁移后统一落 `<paper_dir>/figures/`。

## 独立任务：仅从 minerUmd 写完整 Figure解读

用户常说「Write complete Figure解读 note for `<ckey>` from minerUmd」——**不跑 MinerU 全流程**，在已有 `minerUmd_<ckey>.md` 旁写 `Figure解读_<ckey>.md`。

0. **文首 Overview（强制）**：frontmatter 之后、第一张 Figure 之前写 `## Overview`——4–6 条 `**维度名**：` bullet（研究背景/问题、研究脉络、主要方法、关键结论/意义），读者只看 Overview 即懂全文脉络与方法；禁止长段落。
1. **对齐库内范例**（同 vault `05 Literature/`）：主图 panel 用 是什么/为什么/怎么做/**发现** 四维；补充图**与主图相同格式**逐图排版（可参考 `nishide`、`shimagami`、`dann` 等已写笔记）。
2. **先通读 minerUmd 全文**（含 Results + Methods 中对 fig. S 的引用），再写；勿只扫 Figure 标题。
3. **图注来源优先级**：minerUmd 内完整 Fig legend → canonical 主 PDF（`<paper_dir>/<citation_key>.pdf`，PyMuPDF 抽文本）→ 补充 PDF（`attachments/` 内，若有）→ 正文/方法归纳（必须标明，见下）。
4. **Science / 主文 PDF 无 SM 图注时**：minerUmd 往往只有 Fig.1–6 完整 panel 图注，S1–S33 仅正文 `fig. Sx` 引用。**禁止**留空或假写逐字 SM legend。应：
   - 主图：尽量用 PDF/minerUmd **逐字** legend 放进 `>`；
   - 补充图：**仍逐图排版**（`## Figure S…`＋图片嵌入＋`> **叙事位置**`＋逐 panel 四维解读）；「原文 Legend」写正文/方法指向的内容摘要，并在该图下注明：*主 PDF 无完整 SM 图注；此 Legend 据正文引用与 Methods 归纳，非出版社逐字图注*。
5. **高清插图渲染（与完整流程同规）**：所有 `![[<64位hex>.png]]` 必须由 `scripts/render_pdf_figure.py` 从该篇 **canonical 主 PDF**（`<paper_dir>/<citation_key>.pdf`）以 300dpi 渲染的**完整整图**，落该篇 `<paper_dir>/figures/` 后在 `## Figure X/SX` 标题之后、叙事之前嵌入；minerUmd 中同一 embed 插在对应 legend 前（若缺失）。每图只放完整整图；定位流程与不可靠声明见「图片嵌入」节。
6. **落盘**：中文路径必须用 `terminal` + `python3` + `Path.write_text`；**不要**把含中文的 vault 路径设为 Hermes `terminal` 的 `workdir`（会直接 Blocked）。`workdir` 用英文路径或省略，文件路径写在 Python 字符串里。
7. **自检**：`**是什么**` 与 `**发现**` 计数应接近主图 panel 数；文件通常 >10KB；frontmatter 含最小关系字段 `paper_id` / `citation_key` / `paper: "[[<citation_key>]]"`（**不要**添加 `tags`、`type`）；文首含 `## Overview`（4–6 条 `**维度名**：` bullet）；每张 Figure 标题后有且仅有一张 `![[<64位hex>.png]]` 高清整图（或「原 PDF 未能可靠定位完整 Figure」声明）。

## Overview（文首必填）

- **位置**：frontmatter 之后、第一张 Figure（`## Figure` / `## 补充图`）之前
- **形态**：4–6 条 bullet，每条以 `**维度名**：` 开头（维度名自行归纳，如 研究背景 / 研究问题 / 研究脉络 / 主要方法 / 关键结论 / 临床意义）
- **内容覆盖**：研究背景与问题、研究脉络（问题提出 → 思路 → 分析主线）、主要方法（实验模型/数据来源/核心分析）、关键结论与意义
- **语言**：中文，术语保留英文
- **写作目标**：读者只看 Overview 就能清晰理解该文的研究脉络、研究背景和主要方法；**不要写成长段落**，每条 1–2 句紧凑叙述
- **验收**：`## Overview` 出现在 `## Figure` / `## 补充图` 之前；其下正文区含 4–6 条 `- **…**：` bullet

## 格式规则

### 主图 (Figure 1–7)

⚠️ **禁止合并 panel**：每个 panel（A, B, C, ...）必须独立写成 `**Panel X — 描述**` 块，含各自的 `>` legend + 四维解读。**绝对禁止**把 A–D 所有 panel 写在一个四维块里。H–J 等多 panel 共享同一种解读时才是唯一例外（明确标注哪些 panel 合并）。

1. **标题**：`## Figure X. Title`（粗体 + 编号 + 原文标题）
2. **叙事位置**：引用块 `> **叙事位置**：...`，一句话概括该图在论文逻辑中的位置
3. **每 panel 的合并格式**：
   - `**Panel X — 简短描述**`
   - `> 原文 figure legend`（直接引用论文原文中的图注）
   - `- **是什么**：` 图中展示的内容
   - `- **为什么**：` 做这个分析/实验的原因
   - `- **怎么做**：` 方法简述 + **实验模型/数据来源标注**（见下方「怎么做」增强规则）
   - `- **发现**：` 该 panel 的核心结果/结论——发现了什么（见下方「发现」撰写规则）
4. **原文 legend 不可删**，必须和解读放在同一个 panel 块里
5. H–J 等多 panel 共用解读时可合并，此时「发现」也合并叙述

### 补充图 (Figure S1–Sn / Extended Data)

**补充图与主图相同格式**：逐图排版，旧表格格式已废弃。每张补充图：

1. **标题**：`## Figure SX. Title`（与主图同级）
2. **图片嵌入**：`## Figure SX` 标题之后立即 `![[<64位hex>.png]]`（渲染的高清整图，多图按原顺序；不可靠时写「原 PDF 未能可靠定位完整 Figure」，不得猜裁）
3. **叙事位置**：`> **叙事位置**：...` 一句话
4. **逐 panel**：`**Panel X — 简短描述**` + `>` 原文 legend + `- **是什么/为什么/怎么做/发现**`——与主图完全一致
5. **缺出版社 legend 时**：仍逐图排版；该图下注明「据正文/Methods 归纳，非出版社逐字图注」，禁止空图

**当 ED 图较多（≥8 张）时，按主题分块**，每块一个 `###` 小标题，块内仍是逐图排版。分组示例（Elmentaite 2021，15 张 ED 图 → 7 块）：

```
### ED Fig. 1–4: 数据质控与 BEST4 细胞分析
### ED Fig. 5–7: 上皮细胞补充分析
### ED Fig. 8–9: 肠道神经系统发育
### ED Fig. 10–11: LTi 样细胞鉴定
### ED Fig. 12–13: 内皮和间质细胞
### ED Fig. 14: B 细胞和 BCR 分析
### ED Fig. 15: Crohn's 病中的异位淋巴组织形成
```

## 「怎么做」增强规则

「怎么做」必须在方法简述的基础上，根据实验类型注明实验模型或数据来源：

### 湿实验 → 注明实验模型

在方法描述中自然嵌入实验模型信息：

| 实验类型 | 标注内容 | 示例写法 |
|---------|---------|---------|
| 流式细胞术 (Flow) | 细胞来源/模型 | `流式检测 HLA-DR⁺ 比例，**模型：健康人外周血 CD66b⁺ MACS 分选中性粒细胞 (n=3)**` |
| 免疫组化/荧光 (mIHC/IF) | 组织来源 | `mIHC CD15 + HLA-DR 共染，**模型：多癌种 TMA (n=68)**` |
| 动物实验 | 品系+模型 | `**动物模型：C57BL/6 小鼠 LLC/MC38/Hepa 1-6 皮下瘤**，1.5% 亮氨酸饮水 (n=7/组)` |
| 体外细胞实验 | 细胞系/原代来源 | `**细胞模型：dHL-60 细胞系**，RFX5 敲减/过表达 → 流式` |
| 临床样本检测 | 样本类型+n | `ELISA 检测血清细胞因子，**样本：HCC 患者术前血清 (n=25)**` |
| 电镜 (TEM) | 样本来源 | `TEM 观察线粒体超微结构，**样本：亮氨酸刺激 24h 后人外周血中性粒细胞**` |

### 干实验 → 注明数据来源

| 分析类型 | 标注内容 | 示例写法 |
|---------|---------|---------|
| 转录组分析 | 数据来源+样本量 | `**数据来源：TCGA bulk RNA-seq (8,766 样本, 31 癌种)**，3 算法 consensus score` |
| 单细胞分析 | 数据来源+细胞数 | `**数据来源：17 癌种自产+公共 scRNA-seq 整合 (143 患者, 225 样本, ~18 万细胞)**` |
| 表观组分析 | 数据来源+技术 | `**数据来源：亮氨酸刺激中性粒细胞 CUT&Tag (n=3)**，H3K27ac 差异峰分析` |
| 蛋白质组 | 数据来源 | `**数据来源：CPTAC 蛋白质组数据 (n=1,033)**` |
| 公共数据库 | 数据库名+数据类型 | `**数据来源：GEO (GSE103322)** 胶质瘤 bulk RNA-seq` |
| 生存分析 | 数据来源+队列名 | `**数据来源：TCGA + 8 个已发表免疫治疗队列 (SKCM/STAD/HCC/BLCA/NSCLC)**` |

### 通用原则

- **无法确定模型/来源时**：写 `**模型/来源：原文未明确说明**`，不得编造
- **原文只提方法不提模型**：写清楚方法，补充 `**（模型信息原文未提及）**`
- 模型信息尽量嵌入方法描述中，不要单独一行，保持紧凑
- 统计检验、样本量 (n=) 等照常写，与模型标注一起构成完整的方法叙述

## 「发现」撰写规则

「发现」回答"这张 panel 的结果揭示了什么"，是对结果的浓缩叙述，不是对「是什么」的重复。

### 写作原则

1. **基于原文 body text 中对该 panel 的描述**，直接提取结论性语句
2. **与「是什么」区分**：「是什么」描述图里画了什么（横轴/纵轴/颜色代表什么），「发现」描述从图中读出了什么结论
3. **简洁**：通常 1 句话即可，复杂 panel 至多 2 句
4. **不确定就写不确定**：如果原文对该 panel 的结论表述模糊，写 `**发现**：原文未明确结论`，不要自行推断
5. **保留原文语气**：若原文用 "suggesting that..." / "indicating..." 等谨慎措辞，同步保留，不要升级为肯定句

### 示例对比

| Panel 内容 | ❌ 不好（重复「是什么」） | ✅ 好（聚焦结果） |
|-----------|------------------------|-----------------|
| Flow 检测 HLA-DR⁺ 比例 | `发现：亮氨酸组 HLA-DR⁺ 比例高于对照组` | `发现：20 种氨基酸中，亮氨酸最显著上调 HLA-DR⁺ 中性粒细胞比例` |
| UMAP 降维 | `发现：UMAP 显示 10 个亚群` | `发现：肿瘤中性粒细胞存在 10 种转录异质性状态，涵盖炎症、趋化、抗原呈递等功能模块` |
| 生存 KM 曲线 | `发现：高 HLA-DR⁺ 组生存优于低组` | `发现：HLA-DR⁺ 中性粒细胞高浸润与良好预后显著相关（log-rank p<0.001），独立于癌种和分期` |
| Seahorse OCR | `发现：亮氨酸组 OCR 更高` | `发现：亮氨酸刺激显著增强中性粒细胞线粒体氧化呼吸能力，基础呼吸和最大呼吸均上调` |
| TCGA Cox | `发现：HLA-DR⁺ signature 保护效应` | `发现：HLA-DR⁺ CD74⁺ signature 在 8 个免疫治疗队列中一致预测更好治疗响应和生存` |

### 特殊情况

- **质量控制 panel**（如 Fig 1C 展示样本数/细胞数统计）：`**发现**：研究共纳入 143 患者/225 样本/~18 万中性粒细胞，70.59% 为自产数据`
- **实验流程图/策略图**（如 Fig 4A 体外筛选策略）：`**发现**：该 panel 为实验设计示意，非数据展示——展示了 20 氨基酸 → CD66b⁺ MACS → 多组学读取的筛选流程`
- **原文未对该 panel 单独下结论**：`**发现**：原文未单独讨论此 panel 的结论`
- **panel 为对照/验证性质**：如实写，如 `**发现**：MHC-I 基因在亮氨酸刺激后无显著变化，确认亮氨酸特异性调控 MHC-II`

## 解读撰写要点

- **严格基于原文**：所有解读（尤其「发现」和「怎么做」的模型/来源标注）必须来源于全文中对应 Figure 的 body text 段落，不编造
- **What**：根据原文 Legend 和正文描述该 panel 展示的内容
- **Why**：根据正文中"...we asked whether..." / "...to address this..." 等句式提取动机
- **How**：样本量 (n=)、算法/试剂、统计检验（t-test / Wilcox / log-rank）+ **实验模型或数据来源**（见上方增强规则）
- **Finding**：该 panel 的核心结果——从原文中提取结论性语句，不编造，不确定就写不确定
- **语言**：中文，专业术语保留英文（如 scRNA-seq, mIHC, pseudotime 等）
- **不要添加**：原文未提及的样本量、未报告的统计值、过度解读的生物学结论

## 输出自检（生成 Figure解读 后必须逐项确认）

- [ ] 每个 `## Figure X` 下，panel 块数 ≥ legend 中的字母数（A, B, C, ...）
- [ ] 不存在"一个四维块覆盖 A–D 所有 panel"的情况（共享解读的 H–J 除外，且已明确标注）
- [ ] 每 panel 的「发现」是其**自己**的结果/结论，不是全景概括

## 方法概要（可选）

当论文的核心计算方法（如 Milo、cell2location、NMF、fGWAS 等）贯穿多张 Figure 且细节分散在 Methods 各处时，可在所有 Figure 解读之后追加 `## 方法概要` 节，按方法分段列出关键步骤和参数。这为后续查阅提供快速参考，避免每次都要回到 minerUmd Methods 中搜索。

- **触发条件**：论文中有 ≥2 张 Figure 依赖同一复杂计算方法，且该方法在正文/图注中仅简略提及（如"as determined by Milo analysis"）
- **不替代 panel 级「怎么做」**——每个 panel 仍需在「怎么做」中简述其具体用到的分析步骤；方法概要只做集中归纳
- **格式**：`### 方法名` + 编号列表（关键词/参数用粗体）

示例（Elmentaite 2021）：

```
## 方法概要

### Milo 差异丰度分析

1. 对 BEST4 肠细胞进行 PCA 降维和 **KNN 图**构建
2. 从 KNN 图中采样节点构建"邻域"（neighbourhood）
3. 对每个邻域进行假设检验：小肠 vs. 大肠（**10% FDR**）
4. 差异基因表达分析：**limma**（10% FDR，aggregateSamples=TRUE）
5. GO 富集分析：**clusterProfiler**

### Cell2location 空间映射

1. **负二项回归模型**估计 65 个细胞群参考特征（13,904 基因，124,049 细胞）
2. 在 **Visium** 数据上解卷积（4,645 spot，3 个实验联合）
3. **NMF** 分解（17 factors）识别组织区域
4. 参数：N̂ = 12, Â = 8, Ŷ = 4, 40,000 训练迭代
```
